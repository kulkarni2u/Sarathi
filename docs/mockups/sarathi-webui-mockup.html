Architecture

Last edited by sweethome · 4 days ago · human-authored · linked to 3 tasks

The payments platform splits into a synchronous checkout service and an asynchronous settlement pipeline. All money-moving operations flow through the PaymentIntent aggregate — the single source of truth for a transaction's lifecycle.

PaymentIntent lifecycle

States: created → authorized → captured → settled, with refunded and failed as terminal branches. Transitions are being migrated to a typed state machine (see pending proposal above).

Webhook delivery

Provider webhooks ingest via an SQS FIFO queue keyed by payment_intent_id to guarantee per-transaction ordering. Idempotency is enforced at the handler boundary.
