# Changelog

All notable changes to Sarathi are documented here.

## Unreleased

### Added

- Added NCP improvement records for policy proposals (direct mode): each
  proposal LEARN generates is filed as an NCP improvement attempt under a
  problem named by its title, and accept / reject / rollback set its status.
  New proposals carry the problem's earlier attempts (`improvement` on the
  proposal artifact), including whether the same change was rejected or
  rolled back before.
- Added a post-accept check for accepted proposals: LEARN logs each task's
  measured outcome (`.sarathi/ncp_outcomes.jsonl`) and, once enough tasks of
  the proposal's task class have run on both sides of the acceptance,
  compares success rates. A drop below `post_accept_gate_ratio` x the
  pre-accept rate is reported in LEARN's `post_accept_checks` with a rollback
  command and recorded on the NCP attempt; nothing is rolled back
  automatically. Thresholds: `learn_evolve.post_accept_min_outcomes` (5) and
  `post_accept_gate_ratio` (0.9) in `escalation.md`.
- `.ncp/run.py` bridge version 3 adds `improvement_record` and
  `improvement_update`.

- Added NCP outcome feedback: LEARN records each task's measured outcome in
  NCP (`record_outcome`), crediting the NCP chunks the task read and wrote, so
  NCP raises the trust of memory behind successful work and lowers it for
  memory behind failures. Failure is any failed phase, a rollback, or a
  failed VERIFY command; a real VERIFY command counts at full weight
  (`eval_source: verifier`), anything else at half (`self_report`). The
  result is stored as LEARN's `artifacts["ncp_outcome"]`; feedback never
  fails LEARN.
- The `.ncp/run.py` direct bridge (version 2) takes a caller-chosen
  `chunk_id`, prints `written:<id>` / `suppressed:<id>` from `write_memory`,
  and adds `record_outcome`, which also runs NCP's feedback calibration
  unless `[calibration].auto_on_outcome = false`. `sarathi init` upgrades a
  bridge generated by an earlier release and keeps the old copy as
  `.ncp/run.py.bak`.

- Added `sarathi autoresearch` (`register`/`evidence`/`verdict`/`list`) for
  pre-registering hypotheses and recording evidence and verdicts as an
  append-only `.sarathi/autoresearch.jsonl` log.

### Changed

- An escalated phase now makes a task a failure in the outcome reported to
  NCP and in the post-accept check (it needed a human). Configurable with
  `learn_evolve.failure_outcomes` in `escalation.md` (default
  `[fail, escalate]`; `[fail]` restores the previous rule).

- Raised the `neural-context-protocol` floor to `>=1.9.7` (required for
  `ncp handoff --return`).
- Made recovery failure classification, engine gate thresholds and
  remediation text, and the learn-evolve deviation threshold
  policy-configurable via `escalation.md`/`review.md` instead of hardcoded in
  the engine and runtime.
- Propagated `HarnessConfig` into graph-node dispatch (FANOUT/JUDGE/
  SYNTHESIZE) so child-task dispatch declares a harness before running,
  matching the single-task ROUTE path.

### Fixed

- Fixed graph-node signals reaching the wrong nodes. In direct mode,
  FANOUT/CLASSIFY/JUDGE "whispers" were plain memory chunks and nodes found
  them with a memory search that falls back to recent chunks, so every
  branch (including ones nothing was sent to) received other tasks' signals
  and unrelated memory. They are now real NCP whispers, addressed to the
  node and scoped to the task (`sarathi_<task_id>`), read only by their
  target and acknowledged after it succeeds; a JUDGE's winner node now reads
  its signal too. In MCP mode, emits used `fanout_context`-style types NCP
  rejects, and the JSON-RPC error was never checked; they now use NCP's
  `nudge` type and report errors. Requires the version-4 `.ncp/run.py`
  bridge (`sarathi init` upgrades it).
- Fixed harness-outcome policy proposals never firing in normal use: the
  Evolver's per-task-class quality baselines lived only in memory, so every
  `sarathi run` started without one. Baselines are now persisted
  (`.sarathi/evolve_baselines.json`) as the mean of the last
  `learn_evolve.baseline_window` values (default 20), compared once
  `baseline_min_samples` (default 1) exist.
- Fixed quality-signal deviation being absolute: any change in `token_cost`
  or latency (counts in the thousands) exceeded the 0.1 threshold. Deviation
  is now relative to the baseline's magnitude, so rates behave as before and
  counts use the documented 10%; and a lower `token_cost`, latency,
  `blast_radius` or rollback rate is reported as improved, not degraded.

- Fixed NCP MCP mode, which was broken outside handoffs: cost logging called
  `ncp_log_cost`, a tool NCP does not have, so every call failed (it now uses
  `ncp_post_turn` without acknowledging pending whispers); and `ncp_fetch` /
  `ncp_get_context` results were passed on still wrapped in their JSON
  envelopes, so callers received JSON instead of chunk blocks and context.
- Fixed NCP handoff dispatch failing on every call: the `share` whisper
  payload was a pipe-delimited string, which NCP rejects (it validates
  `share` payloads as `HandoffPayload` JSON since 1.2.1). The payload is now
  bounded `{"ask", "slice", "files"}` JSON.
- Fixed NCP handoff returning truncated provider output to downstream
  phases: NCP 1.9.6+ prints a ≤2,000-char summary by default, so Sarathi now
  runs `ncp handoff <provider> --return full`.
- Fixed `sarathi init`'s NCP config overrides never taking effect: they were
  appended after the last TOML table (landing in `[embedding]`), and
  `max_chunk_tokens` was never an NCP setting. Init now writes
  `[pipeline] default_ttl_hours = 168` and `[tools] profile = "standard"`
  into the correct tables, keeps values the user changed, and removes the
  old block from existing `.ncp/config.toml` files on re-init.
- Fixed `sarathi autoresearch` crashing on a corrupted store file; malformed
  JSONL lines are now skipped instead of crashing every future invocation,
  and `KeyError` messages no longer print with stray quotes.
- Fixed a `mypy` duplicate-module error caused by the dual `src`/relative
  import pattern, via `[tool.mypy]` config rather than a package rename.
- Fixed stale CLAUDE.md documentation (service-layer file-size claims) and
  added the missing `policy-pack/EXAMPLE/workflow-patterns.md`.

## 0.3.0 - 2026-06-17

### Added

- Added the Sarathi WebUI cockpit: Dashboard, Task Studio, Needs You, History,
  Settings, Agents, Knowledge, Skills, Wiki, Proposals, Usage, and Workspace
  views backed by the local service API.
- Added the Electron desktop shell that launches the shared Sarathi service and
  web cockpit with runtime configuration injection.
- Added project-scoped task chat from the Dashboard and task-scoped chat in
  Task Studio, including provider-backed replies through the same free-form
  chat path used by the TUI.
- Added governed Task Studio workflows for PRD/AC approval, task-graph drafting,
  ready-unit scheduling, provider dispatch, evidence review, final handoff, and
  repository-action gates.
- Added service-owned workspace and project APIs so the WebUI, Electron app,
  TUI, and CLI can share the same persisted state.
- Added provider Settings for Claude, Codex, Copilot, OpenCode, and local
  deterministic execution, including connection testing and provider health.
- Added role-derived provider permissions with `read_only`, `read_write`, and
  `full` modes instead of relying on global provider auto-approval config.
- Added Sarathi session-start hooks and bundled policy guidance for Claude,
  OpenCode, and other agent sessions to auto-detect and collaborate with
  Sarathi.
- Added Docker-compatible sandbox execution with Docker and Podman support,
  environment-based runtime selection, and daemon-gated integration tests.
- Added deterministic repo wiki generation and workspace bootstrap behavior that
  preserves existing human-authored policy and wiki files.
- Added service auth, SSE/event polling, OpenAPI documentation, static file
  serving, session/co-drive APIs, operational projections, and usage stats.

### Changed

- Made the local service the source of truth for cockpit state, task messages,
  approvals, graph projections, evidence, review runs, handoff, projects, and
  workspace knowledge.
- Updated `sarathi init` and desktop workspace bootstrap to create or reuse
  policy packs and local wiki assets without overwriting user-authored files.
- Updated provider dispatch to compile compact task-specific context packs and
  derive permission mode from agent role and task metadata.
- Updated Task Studio provider selection to normalize provider IDs before
  dispatching graph units.
- Updated dashboard task grouping and project filters to use live service
  projections rather than mock data.

### Fixed

- Fixed stale approval-gate handling so superseded pending gates do not keep the
  Task Studio header in `awaiting_approval`.
- Fixed graph approval dispatch so approving the task graph schedules ready work
  when auto-scheduling returns no units.
- Fixed review/handoff flow so an approved review can be created from already
  completed subtasks that have dispatch evidence.
- Fixed Review tab refresh behavior so running a review updates the visible
  review list without requiring a page reload.
- Fixed OpenCode project configuration by removing reliance on the invalid
  legacy `autoapprove` setting.
- Fixed desktop Python runtime selection so the Electron app starts with a usable
  interpreter.

### Validation

- Full Python suite passed locally after merge: `1087 passed, 8 skipped`.
- Web production build passed: `npm --prefix web run build`.
- Live browser walkthrough verified PRD approval, task-graph approval, DAG
  dispatch, review approval, and handoff generation against the local service.
